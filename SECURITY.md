Reporting a Vulnerability
We take the security and stability of this project seriously. If you discover a security vulnerability or a potential leak/exploit related to DPI bypass mechanisms, please report it responsibly.

How to Report
Please DO NOT open a public GitHub issue for security vulnerabilities or zero-day exploits.

Instead, please report vulnerabilities through one of the following channels:

GitHub Security Advisories (Preferred): Go to the Security tab of this repository, click on Advisories, and select Report a vulnerability.

What to Include in Your Report
To help us investigate and resolve the issue quickly, please include:

A clear description of the vulnerability and its potential impact.

Steps to reproduce the issue (including standard configuration flags, command-line arguments, or specific ISP/DPI setups tested).

Any relevant logs, screenshots, or packet captures (.pcap).

Operating System version and architecture (e.g., Windows 11 x64).

Response & Resolution Timeline
Initial Acknowledgement: We aim to acknowledge receipt of your report within 48 hours.

Status Updates: You can expect status updates at least once every 5 to 7 business days while we investigate and draft a fix.

Triage & Patching: If accepted, a patch will be prepared in a private repository and tested prior to a public release.

Public Disclosure: Once a security patch is released, we will credit you in the release notes (if desired) and publish a CVE / Security Advisory where applicable.
